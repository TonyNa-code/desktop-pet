Safer chat and voice responses, with existing characters and preferences preserved.

## Changes

- Voice services can no longer direct audio downloads to arbitrary websites, loopback addresses or internal-network services. A returned audio link must use the same origin as the voice endpoint you configured.
- Chat and voice requests reject redirects. Use the service's final endpoint URL in settings.
- Chat, audio and error responses have byte limits before parsing or playback, preventing oversized responses from consuming unbounded memory.
- Known saved and newly entered service keys are redacted from provider error messages before they are displayed or saved in chat history.
- Voice data URLs accept audio formats only.

## Voice Compatibility

Direct audio responses and base64 audio remain supported. An audio URL must have the same scheme, hostname and port as the configured TTS service. If a service returns a separate CDN address, use its direct-audio response option or a same-origin audio endpoint instead. Explicitly configured local GPT-SoVITS endpoints remain supported.

Limits are 2 MiB for chat responses, 24 MiB for audio and 32 KiB for provider errors. Existing request timeouts remain in place. Voice, saved history and shared memories remain off by default. This update does not add a model service, microphone access or automatic network requests.
